# v0.3 P4 — 完整流程、回归与发布验收

**结论：PASS（v0.3.0 增量 Gate）**。P0–P3 记录和 P4 的隔离浏览器、Live、导出、恢复、安全扫描及全量回归已完成。此结论只覆盖 v0.3.0 增量，不会改写既有 M0–M6 验收报告中的历史记录。

## Case 与环境

使用一条虚构的公开信息研究目标：“研究如何构建本地优先的 Agent 管理仪表盘，展示多个 Agent 在线状态与最近活动，并要求响应式网页、JSON 导出、逐项核实开源许可，未测试接口保持未知”。测试服务位于 `127.0.0.1:8012`，数据目录为 `/private/tmp/goalsift-p4-live-20261013`，仅有一个合成任务 `job_99d6ae93275f4571`。没有读取或写入用户原有的 8000 端口页面和数据库。

服务端单修订上限 `$0.12`，并限制 40 个动作、24 次工具调用、300 秒和 3 轮检索；P4 总预留上限 `$0.30`。费用来自应用记录，不是 DeepSeek/Exa 的账单。

## 完整流程与观察

第一修订曾因动作上限到达检查点，随后在同一任务上恢复并完成：9 条条件、8 个资源、72 项评估，记录费用 `$0.0693626`。测试操作者在该修订记录了待核验倾向。

第二修订提出了澄清问题。测试操作者明确保留原始约束，只对照证据、不选择技术栈或组件、不执行实施，许可证与未测试接口缺乏来源时继续标记 UNKNOWN。研究完成后得到 10 条条件、8 个资源、80 项评估；费用 `$0.0639041`。结果把缺少证据、尚未在目标环境测试和后续核验步骤分开说明，没有把来源支持说成实测通过。

界面显示旧决定需要重新确认。操作者为当前修订选择“仅作为核验路径的阶段性倾向”的方案，并在采用前清单保存一条 `FOLLOW_UP` 注记，明确目标环境测试尚未建立、许可和传递依赖仍待核验。它没有创建 Evidence，也没有改变任何 Assessment。第二修订的清单共 27 项，其余仍待检查。

在浏览器实际查看了当前方案和检查清单、切换到只读历史修订、刷新返回当前修订、确认旧决定待复核、保存跟进注记，以及打开 Markdown/JSON 下载。桌面 1280×720 页面信息可读；390×844 首次发现横向滚动，修复主内容滚动区后重新检查，窄屏不再横向移动。修复与视觉检查记录见 `P4_UI_AUDIT.json`。屏幕截图在本轮浏览器会话中人工审阅；浏览器工具只提供会话内图片，没有受支持的路径将其保存为文件，因此验收目录没有截图二进制。

## 导出与恢复

`P4_HANDOFF.json` 可解析，包含第二修订、10 条条件、8 个资源、80 项评估、135 条证据、当前选择注记版本 2 和 27 项清单。Markdown 与 JSON 的方案标题、选择理由和跟进备注逐项一致。两种制品分别为 1,053,702 与 125,464 字节，哈希及检查结果见 `P4_EXPORT_AUDIT.json`。
